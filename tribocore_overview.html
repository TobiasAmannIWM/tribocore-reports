Gold standard: B3P (Ball-on-Three-Plates)

The fully integrated reference method. All other tribological methods replicate its integration depth: FAIR-JSON, Neo4j edges, Fuseki triples, ML datasets, and HAS_COMPLEMENTARY_DATA cross-links to lubricant characterisation experiments.

Connected knowledge graph — not isolated Excel files

Every experiment links to its material (USES_MATERIAL), lubricant (USES_LUBRICANT), and characterisation experiments of the same lubricant (HAS_COMPLEMENTARY_DATA). Cross-method graph connectivity is the primary value of TriboCore.

FAIR & MaterialDigital compliant

All 6 Hartrott/PMDco recommendations implemented: PMDco crosswalk, IAO textual definitions, SHACL 0 violations, one named graph per method in Fuseki, RepeatGroup nodes, and complete OWL class hierarchy per DIN/ISO norms.

Deployment: Single-user local Streamlit app on Windows via Miniforge Python. Neo4j and Fuseki run as local services. All data stays on-premises. Architecture supports straightforward migration to an institutional server with read-only SPARQL federation once a centralised IWM deployment is needed.

④ Cross-Method Analytics — ML & AI Query Interface
Three ML modules operate on the unified multi-method dataset via load_multi_method_dataset(). A Chatbot (local Ollama LLM) translates natural-language questions into SQL against the SQLite FAIR database.
Multi-Method CoF Prediction (RF + SHAP)

Random Forest trained on 5 tribological methods simultaneously. Feature importance: Hertz contact pressure ~35 %, sliding distance ~20 %, viscosity ~15 %. R² ≈ 0.60 cross-validated. SHAP waterfall plots per experiment.

Bayesian GPR — Uncertainty Quantification

Gaussian Process Regression with RBF + White kernel. Provides 95 % confidence bands around predictions. Useful for interpolation between unmeasured test conditions (temperature, load) within the same material/lubricant system.

AI Chatbot — Natural Language to SQL

Local Ollama LLM generates SQLite queries from plain English. Example: "Which lubricant shows the lowest mean CoF at contact pressure above 1 GPa?" All 11 methods registered in the SQL system prompt; debug SQL visible in UI.

⑤ Outputs & TriboViewer
Every method produces a standardised output set at three levels: per experiment, per project, and global. HTML reports are self-contained client deliverables generated automatically from the same pipeline.

  • Excel summary (all Kennwerte)

  • Overview PPTX (summary plots)
  • Combined PPTX (all experiment reports)
  • Combined FAIR-JSON (project-level)

B3P TriboViewer — Interactive Features
Stribeck Curve Overlay

Multi-experiment comparison on a single Stribeck plot with automatic log x-axis. Mean curves with std deviation bands. Up to 10 experiments per overlay. Filter by project, lubricant, condition, or material pairing.

Regime Detection — 12 Kennwerte

Automatic lubrication regime classification (boundary / mixed / EHD / hydrodynamic) per Stribeck interval. 12 output columns: regime, CoF at boundary/minimum/EHD, transition velocities, film thickness ratios.

Friction Work with Axis Break

Run-in friction work as first bar with visual crossing-line axis break. Fixed y-axis defaults for cross-experiment comparability. Slider control enables dynamic range adjustment. PPTX export directly from viewer.

AutoSync: New measurement files placed in the correct folder are automatically detected on the next Dashboard load. Analysis runs in a background subprocess without blocking the Streamlit UI. Registry updates and Neo4j/Fuseki sync follow automatically.

Concrete Next Steps
1. SRV LSM wear integration

Add post-test microscopy workflow: W_K (DIN 51834-2 §10.1 wear scar diameter, measured by microscope) and W_V (volumetric wear via LSM). Column layout pre-defined in srv_data_dictionary.py; folder structure specified in Phase 0.

2. Historical B3P/GLEX dataset integration

Experiments from 2018–2023 exist as Excel files. Batch import via backwards-compatible filename parsers extends the knowledge graph retroactively; all cross-method HAS_COMPLEMENTARY_DATA links propagate automatically to historical records.

3. Institutional Fuseki endpoint

Once the local Fuseki instance is confirmed complete, a read-only IWM server endpoint enables cross-institutional SPARQL federation. All named graphs and PROV-O provenance are already in place; only the server deployment step remains.
